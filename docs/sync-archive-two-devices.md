# Проверка архива на двух устройствах

Автоматическая часть уже проверена: `tests/sync-crypto/run.sh` собирает тест из
настоящего `teleforge_sync_crypto.cpp` и подтверждает, что одинаковый пароль даёт
одинаковый ключ на двух «устройствах», а неверный пароль не открывает архив.
Ниже — ручная проверка того же через приложение и настоящую базу.

## Что понадобится

- Два рабочих каталога на разных машинах (или два каталога на одной).
- Один аккаунт Telegram — тот же на обоих.
- Общая база: PostgreSQL, доступная по SSH-туннелю (клиент умеет его поднимать).
- Один и тот же пароль архива.

## Порядок

**ПК №1 (источник данных).**

1. Настройки → Синхронизация → провайдер «PostgreSQL», заполнить host/port/db/user/password, «Сохранить подключение», «Проверить подключение».
2. Включить SSH-туннель, если порт базы не опубликован.
3. В поле «Пароль архива» ввести пароль, нажать «Сохранить пароль архива».
4. Нажать «Перешифровать облачный архив этим паролем» — это перезаливает всю локальную базу уже под ключом аккаунта.
5. Дождаться окончания загрузки (прогресс внизу окна).

**ПК №2 (второе устройство).**

1. Войти в тот же аккаунт — рабочий каталог другой, значит и секрет устройства другой.
2. Подключить ту же базу так же, как на ПК №1.
3. Ввести **тот же** пароль архива.
4. Запустить синхронизацию и убедиться, что подтянулись удалённые и изменённые сообщения, история онлайна и архив пользователей.

**ПК №3 (негативная проверка).**

1. Войти в тот же аккаунт, подключить ту же базу.
2. Пароль **не вводить**.
3. Синхронизация должна не расшифровать чужие бандлы: данные останутся недоступны, ошибок чтения в интерфейсе быть не должно.

## Что смотреть в базе

Зашифрованная строка выглядит как base64 от `TFSYNC2` + mode + salt + nonce +
шифротекст + тег, и **никогда** не содержит читаемого JSON:

```sql
select tenant_id, left(payload, 16) from teleforge_messages limit 5;
```

Если в `payload` видно `{"id": ..., "text": ...}` — значит в базу писал кто-то
помимо клиента, и это надо разбирать отдельно (именно так было с веб-сервисом
`tgweb`, который удалён).

## Известные ограничения

- Без пароля архив читается только на том устройстве, где он создан: ключ
  выводится из секрета устройства.
- Смена пароля не перешифровывает автоматически: после смены нужно снова нажать
  «Перешифровать облачный архив».
- Суперпользователь базы обходит RLS-политики из `packaging/postgres-rls.sql`;
  конфиденциальность держится на шифровании, RLS — только разграничение ролей.
